## 先抛结论

Vue3 必须用 `.value`，是 JavaScript 这门语言本身的限制导致的，而非 Vue 故意设计复杂。`.value` 是为了让基础类型也能拥有响应式能力。

日常开发里最常见的两种写法：

```js
// 基础类型用 ref，必须加 .value
const count = ref(0)
console.log(count.value)  // 0
count.value++

// 对象、数组用 reactive，不用加 .value
const user = reactive({ name: '张三', age: 18 })
console.log(user.name)    // 张三
user.age++
```

为什么同样是响应式数据，用法天差地别。

## 两种数据类型

要理解 `.value`，得先搞懂 JavaScript 最核心的一个知识点：值类型和引用类型。

| | 值类型（原始类型） | 引用类型 |
| --- | --- | --- |
| 类型 | string / number / boolean / null / undefined / Symbol / BigInt | object / array / function |
| 存储 | 栈内存，直接存值 | 栈内存存地址，堆内存存数据 |
| 传递 | 值拷贝，赋值后互不影响 | 地址拷贝，多个变量指向同一个数据 |
| 关键特性 | 无法被引用，没有「地址」概念 | 可以被引用，改属性会影响所有指向它的变量 |

```js
let a = 10
let b = a
b = 20        // a 还是 10，b 是 20，完全独立

const obj = { count: 10 }
const obj2 = obj
obj2.count = 20   // obj.count 也变成 20，共享同一个引用
```

值类型没有地址，所以没东西可拦。这句话是后面所有事的起点。

## Vue2 的痛点

Vue2 的响应式基于 `Object.defineProperty`，它有一个致命缺陷：只能劫持对象的属性，无法劫持原始值。

```js
let count = 0
Object.defineProperty(window, 'count', {
  get() { return count },
  set(val) { count = val }
})
```

这种方式只能劫持全局变量，没法封装复用。于是留下三个后果：

- 原始类型无法独立响应式，必须包裹在对象里；
- 解构丢失响应式，`const { name } = reactive(user)` 之后就断了；
- 数组需要重写方法，性能开销大。

Vue3 团队的目标很明确：打造一套真正通用、无缺陷的响应式系统，同时支持原始类型和引用类型。

## 引用类型的解法

对于对象和数组，JavaScript 天生支持引用传递，Vue3 直接用 Proxy 劫持整个对象。

`reactive` 接收一个对象，返回一个 Proxy 代理对象。代理对象和原对象用法完全一致，访问或修改属性时自动触发依赖收集和更新。

这就是 `reactive` 不用加 `.value` 的原因：Proxy 完美适配引用类型，没有语法负担。

## 原始类型的困境

核心问题来了：Proxy 只能代理对象和数组，不能代理原始类型。

```js
new Proxy(10, {})
```

我在 `node v22.22.1` 上跑这行，报的是：

```
Uncaught TypeError: Cannot create proxy with a non-object as target or handler
```

这是 JavaScript 标准规定的，不是 Vue 的问题。`reactive(0)` 会把 `0` 原样还回去，顺手打一句 `[Vue warn] value cannot be made reactive: 0`。源码里 `createReactiveObject` 开头判了一下 `isObject`，不是对象就警告，然后 `return target`。

那原始类型怎么实现响应式，只剩一条路：包装成对象。

`ref` 的本质，就是把一个原始类型的值，包裹在一个单属性对象里，用 `.value` 作为唯一访问入口。

```js
function ref(value) {
  return {
    _isRef: true,
    value: value
  }
}
```

这样一来，原始类型变成了引用类型，Proxy 可以正常代理，我们也就能监听它的变化了。这就是 `.value` 的唯一来源：为了突破语言限制，给原始类型套上响应式外壳。

## 源码里长什么样

光看伪代码不够，真源码更能说明问题。

`packages/reactivity/src/ref.ts` 里，`ref` 函数最后走的是 `createRef`，再 `new RefImpl(rawValue, shallow)`。`RefImpl` 这个类不长：

```js
class RefImpl {
  private _value
  private _rawValue
  public readonly __v_isRef = true

  constructor(value, __v_isShallow) {
    this._rawValue = value
    this._value = __v_isShallow ? value : toReactive(value)
  }

  get value() {
    trackRefValue(this)
    return this._value
  }

  set value(newVal) {
    if (hasChanged(newVal, this._rawValue)) {
      this._rawValue = newVal
      this._value = this.__v_isShallow ? newVal : toReactive(newVal)
      triggerRefValue(this)
    }
  }
}
```

`toReactive` 只有一行：`isObject(value) ? reactive(value) : value`。是对象就转成 reactive，是原始值就原样留着。

所以 ref 本质上是 `RefImpl` 类的实例对象。这个对象只有一个公开属性，就是 `value`。读写 `xxx.value`，本质是调类的 get 和 set 访问器：get 收集依赖，set 触发更新。`__v_isRef` 是给框架自己认亲用的标识。

## reactive 那边差在哪

把两边源码摆一起，差别就一行。

```js
new Proxy(target, {
  get(target, key) {
    track(target, key)
    return Reflect.get(target, key)
  },
  set(target, key, value) {
    const result = Reflect.set(target, key, value)
    trigger(target, key)
    return result
  }
})
```

`reactive` 代理的是整个对象，直接访问属性就行；`ref` 代理的是包装对象的 `value` 属性，必须通过 `.value` 访问。

两者底层的依赖收集和更新逻辑完全一致，只是数据载体不同。

## 模板里为什么不用写

`<template>` 里 `{{ count }}` 就够了，这不是魔法，是编译器替你补了。

在 `@vue/compiler-sfc@3.5.45` 上编一段 `<script setup>`，render 里出来的是 `_toDisplayString($setup.count)`，binding 标成 `setup-ref`。真正干活的是运行时那步，`@vue/runtime-core@3.5.45` 的 `handleSetupResult` 里有一句：

```js
instance.setupState = proxyRefs(setupResult)
```

`proxyRefs` 又套了一层代理，读到 ref 自动取 `.value`，写进去自动落到 `.value` 上：

```js
const setup = { count: ref(0) }
const ctx = proxyRefs(setup)
ctx.count      // 0，typeof 是 number
ctx.count = 5  // 等价于 setup.count.value = 5
```

编译器那边认得 `__v_isRef` 标识，运行时这边再兜一层，模板自动解包就是这么来的。

## 解包规则，四条

自动解包有明确规则，边界比想象中窄。

```js
// 顶层 ref：自动解包
const count = ref(0)

// reactive 对象里的 ref：自动解包
const state = reactive({ count })
console.log(state.count)   // 0

// 数组、集合里的 ref：不解包
const arr = reactive([ref(0)])
console.log(arr[0].value)  // 必须写 .value
const map = reactive(new Map([['count', ref(0)]]))
console.log(map.get('count').value)

// 解构出来的是快照
const { count } = state
```

口诀是：顶层 ref 和 reactive 里的 ref 自动解包，数组、集合、解构之后的 ref 必须手动 `.value`。

这几条我都真跑过。`reactive({ inner: ref(3) }).inner` 是 `3`；`reactive([ref('a')])[0]` 是 `RefImpl`；`reactive(new Map([['k', ref(1)]])).get('k')` 也是 `RefImpl`。

还有一处更隐蔽，把新 ref 赋给已经挂着 ref 的属性，旧的会被悄悄换掉：

```js
const count = ref(0)
const state = reactive({ count })
state.count = ref(2)
// state.count 是 2，count.value 还是 0
```

## 全都不用 .value 行不行

很多新手会问：为什么不让 ref 也像 reactive 一样不用加 `.value`，这样不更统一吗。

有两条绕不过去的理由。

第一条是语言死限制，原始类型无法劫持。

```js
let count = $ref(0)
count++
```

这种语法在 JavaScript 里绝对实现不了，因为 `count` 是原始类型，存的是值不是引用，你修改 `count` 只是修改变量本身，没有任何办法监听这个行为。除非 TC39 标准新增语法。

第二条是 Vue 真试过了。

`$ref` 是编译期宏，编译完 `count++` 会变成 `count.value++`。我拿 `@vue/compiler-sfc@3.3.13` 编了一遍，确实如此，连模板字符串里的 `${count}` 都被补成 `${count.value}`，同时 stderr 打一行 deprecation 警告。

换到 `@vue/compiler-sfc@3.5.45`，同一段源码编出来，`$ref` 原样躺着，一个字符没动。真拿 `new Function` 跑 setup：

```
ReferenceError: $ref is not defined
```

构建是过的，运行到那行才炸。2023 年 2 月这个 RFC 被官方放弃，理由里最关键的一条是：少了 `.value`，就看不出哪一行在读响应式数据、哪一行会悄悄触发一次重跑。另外几条也都在：破坏 JS 原生语义、调试困难；解构和传递会出问题；团队学习成本高。

所以 `.value` 是目前最平衡、最可靠、最符合 JS 原生语义的方案。

## 选型

基础类型一律用 `ref`：`count`、`name`、`loading` 这些。

多个关联字段用 `reactive`：一个表单对象，`username`、`password` 摆在一起，写起来像普通对象。

函数返回响应式数据必须用 `ref`，这点我踩过最贵的坑：

```js
// 推荐：ref 可以独立传递，不会丢失响应式
function useCount() {
  const count = ref(0)
  return count
}

// 不推荐：reactive 解构后丢失响应式，不适合独立返回
function useUser() {
  const user = reactive({ name: '' })
  return user
}
```

还有一条：`computed` 里别忘了 `.value`，`computed(() => count.value * 2)`，漏一个就是 `NaN`，而且要等渲染时才炸。

## 一张表

| 类型 | 数据类型 | 实现方式 | 语法 | 核心原因 |
| --- | --- | --- | --- | --- |
| ref | 原始类型 / 对象 | `RefImpl` 包装对象 | `.value` | JS 原始类型无法被 Proxy 代理 |
| reactive | 对象 / 数组 | Proxy 直接代理 | 无 `.value` | JS 引用类型天然支持代理 |

`.value` 不是 Vue 的设计缺陷，而是 JS 语言限制下的最优解。ref 是原始类型的响应式容器，reactive 是引用类型的响应式代理。

我原来也觉得这层壳多余，直到自己用 `Object.defineProperty` 在 `globalThis` 上给裸变量装 getter 和 setter，打点日志确实出来了 `[ 'set:42', 'get' ]`。挺得意，然后想起来线上是 SSR，两个请求同时跑，`globalThis.count` 只有一个位置。

那条路当场就断了。
