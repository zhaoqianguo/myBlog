继上一篇《状态没有名字，React 却一次都没认错》后，我又往下翻了一层。那篇讲 Hook 链表挂在 fiber 的 `memoizedState` 上，fiber 当时只是个背景板，一句「每个组件对应一个 fiber」就带过去了。可要说清一次渲染凭什么能被拆开，躲不掉它。

我一直把 Fiber 当成虚拟 DOM 换了个名字，直到被问到「拆成什么」，才发现自己说不上来。

## 一次渲染原本是一整块

React 把一次更新里做的事统称为 work：更新 state 和 props，调组件的生命周期或者函数本体，拿到新的 children，跟上一轮的结果比一比，算出哪些 DOM 要动。这些事都在 render 阶段做，也叫 reconciliation，做完攒出一张变更清单，再由 commit 阶段一口气刷到页面上。两件事分开，本来是为了让 React DOM 和 React Native 共用同一个 reconciler，各写各的 renderer。

老办法是同步走完整棵树。递归进每个组件，栈一层层压下去，回来的时候再一层层收口，中途没有停的位置。组件树不深的时候没问题，深一点，一帧留给应用代码的 16 毫秒就不够用了，动画开始掉帧。浏览器其实给过 `requestIdleCallback`，回调里能拿到 `deadline.timeRemaining()`，告诉你这一帧还剩多少空闲，我在控制台里见过它报 `49.9 false`。可它触发得不够勤，等不到足够多的空闲帧，React 后来自己写了一套 scheduler。

有了空闲时间也只是有了「什么时候做」，还缺「做多少」。

想让一整块工作能分到几帧里，得先把它切成能一份一份领的单元，而这件事卡在一个很基础的地方。

## 挡路的是调用栈

问题不在树，在递归借来的那个栈。

函数一调用就压一个栈帧，栈帧代表这个函数正在做的事，函数返回才能弹出来。这套结构归运行时管，写代码的人碰不到：它只会一直跑到栈空，你没法在中间说「停在这儿，下一帧接着」，更没法手动挪动栈顶。递归遍历组件树就是把这副栈当成遍历指针用了，树有多深，栈就有多深，遍历的进度全存在这些借来的栈帧里，谁也没把它记在一个能读能写的变量里。

想随时暂停、恢复、丢掉、按优先级重排，就得自己能捏住栈帧。Andrew Clark 在讲 Fiber 的那份笔记里给了个说法：Fiber 是对栈的一次重新实现，专门给 React 组件用的，一个 fiber 就可以看成一个虚拟栈帧。栈帧一旦变成内存里的普通对象，什么时候执行它、要不要复用它，就都由 React 说了算，不用再看运行时的脸色。

## 三个指针撑起一棵树

栈帧放进内存，接下来要解决的是怎么把它们连成原来那棵树的形状。`FiberNode` 上字段不少，真正管连接的是三个：

```js
// FiberNode 里和树形有关的那几个字段
this.return = null;   // 处理完要回到的节点
this.child = null;    // 第一个子节点
this.sibling = null;  // 右边第一个兄弟
this.index = 0;

this.alternate = null; // 另一次更新里对应的那个 fiber
```

`child` 指向组件 render 返回的那一个节点，`sibling` 把同一层返回的多个孩子串成单向链表，`return` 指向处理完当前节点后该回去的地方。我喜欢 `return` 这个命名，它没有叫 `parent`，因为作为一个工作单元，重点不是谁生了我，而是干完活往哪儿回；它对应的其实是栈帧里的返回地址。`child` 和 `sibling` 合起来，就把「往子树里钻一层」和「同一层挨个处理」两件事都表达出来了，每个节点只需要记住自己往下的第一步和往右的一步，不必知道整棵树长什么样。

旁边的 `alternate` 也别跳过。同一个组件实例在任一时刻最多有两个 fiber，一个是已经刷到页面上的 current，一个是正在算的 workInProgress，两者靠它互相指。建新树时会先看旧的那半边能不能复用，能复用就不重新分配对象。这一层是后面「算错了可以丢掉重来」的底。

## 把遍历跑一遍

按这三个指针写一个最小的工作循环，逻辑短得有点意外：

```js
function performUnitOfWork(fiber) {
  beginWork(fiber);              // 算出子节点，挂到 fiber.child
  if (fiber.child) return fiber.child;

  let node = fiber;
  while (node) {
    completeWork(node);          // 收口，攒出这一层的变更
    if (node.sibling) return node.sibling;
    node = node.return;          // 没兄弟了，往回走一格
  }
  return null;                   // 回到根，整棵树走完
}
```

有 `child` 就往下钻，没有就 `completeWork` 收口，然后找 `sibling`，兄弟也没有了就顺着 `return` 往上退，一路上退一路收口，直到退到根之上。整个过程是一个 while 循环加一个变量，栈不再长高，`node` 手里那个就是当前的栈顶帧。真 React 里这一步叫 `completeUnitOfWork`，注释写得很直白：完成当前单元，接着移到下一个兄弟，没有兄弟就退回父 fiber。

拿一个 `App` 组件、里面一个 `div`、`div` 下一段文本和一个 `span`、`span` 里再嵌一段文本拼成树，按上面的循环走，屏幕上打出来的顺序是这样：

```
begin   : App -> div -> i am -> span -> KaSong
complete: i am -> KaSong -> span -> div -> App
```

往下的顺序和递归版一模一样，往上收口却是叶子先来。文本 `i am` 没有子节点，立刻 `completeWork`；轮到 `span`，它得先等自己的 `KaSong` 收完口，所以 `KaSong` 排在 `span` 前面；`div` 又要等两个孩子都完事。这段顺序我盯着看了一会儿，`return` 为什么叫 return，在这里比任何解释都清楚。

## 一个变量就是进度

真正的 work loop 只做一件事：把当前这个 fiber 交给 `performUnitOfWork`，拿回下一个，存进 `workInProgress`。

```js
function workLoopSync() {
  while (workInProgress !== null) {
    performUnitOfWork(workInProgress);
  }
}

function workLoopConcurrentByScheduler() {
  while (workInProgress !== null && !shouldYield()) {
    performUnitOfWork(workInProgress);
  }
}
```

差别全在循环条件上。点击、输入这类交互更新走同步那条，一口气做完；其余的每做完一个单元就问一次 `shouldYield()`，调度器说该让了就退出循环。退出的时候不需要保存现场，`workInProgress` 还指着下一个要处理的节点，下一帧从它接着跑就行，这就是「暂停」的全部实现。我在最小版里试过每两个单元强制让一次，让出的位置分别落在 `i am` 和 `KaSong` 上，回来接着走，遍历顺序一点没乱。

React 里还有一条按时间片收口的写法，`yieldAfter = now() + (nonIdle ? 25 : 5)`：非 idle 的更新攒够 25 毫秒让一次，idle 的 5 毫秒就让。源码注释专门解释了这么做的理由，不是舍不得让出那点开销，是故意把动画压到 30 帧，别让一大段渲染把主线程上的动画饿死。这种数字光看架构图是猜不出来的。

## 能断的只有前半段

可中断的是 render，不是 commit。

render 阶段只算不动：读 props、跑组件、diff、把要删要插要改的记成 `flags` 挂在 fiber 上。算到一半来了更高优先级的更新，这段工作可以直接丢掉，屏幕上还是原来那棵树，用户看不见。等它空下来，从 current 重新克隆一份 workInProgress 再算，之前算过的部分还能靠 `pendingProps` 和 `memoizedProps` 相等来判断能不能复用。也正因为可以随时作废，React 才敢把整棵树拆成一个个单元慢慢领，还敢给不同的更新排优先级。

commit 阶段不一样。这一步真的在动 DOM、真的在跑 layout effect，做一半停下来，用户看到的就是半个界面。所以它没有 `shouldYield()`，进了就得一口气走到底。把一次更新切成两段，代价是要在内存里同时养着两棵树，换来的是前半段可以随便打断、重排、丢弃，后半段短到不值得拆。我觉得这个取舍比「异步可中断」四个字实在得多，它讲清楚了代价在哪一侧。

树收口到根之后，攒下的变更清单交给 commit，根指针从 current 换到 workInProgress，两棵树调换身份，下一轮更新又从 `alternate` 开始复用。上次看 `completeUnitOfWork` 里那句 `completedWork = returnFiber` 我还觉得普通，现在再看，它就是在手动弹栈。
